# Отчет о выполненной работе по проекту TaskMind (ANotes)

В ходе работы в ветке `database` была произведена глубокая модернизация архитектуры данных проекта, реализован новый функционал и обеспечено полное покрытие тестами.

## 1. Миграция базы данных и Core-сущностей
- **Переход на Integer IDs**: Все идентификаторы (`userId`, `projectId`, `taskId`, `projectMemberId`) изменены с `UUID` на `Integer`. Это упрощает интеграцию с фронтендом и повышает производительность БД.
- **Инфраструктура**: Настроена автоматическая инициализация БД через SQL-скрипт `schema-h2-v4.sql`. Отключена автогенерация схем Hibernate для полного контроля над структурой.
- **Обновление моделей**:
    - `User`: Добавлены поля профиля (`displayName`, `avatarUrl`) и флаг активности.
    - `Project`: Добавлены `ownerUserId`, описание, цветовые метки и иконки. Удалена зависимость от файловой системы.
    - `Task`: Расширена структура (автор, исполнитель, статусы, планируемые часы, дедлайны). Тэги переведены на хранение в формате JSON.

## 2. Новая функциональность
- **Статусы проектов (`ProjectStatus`)**: Реализована система настраиваемых статусов для каждого проекта. Добавлены соответствующие Entity, Resource и DTO.
- **Расширенный поиск (`FindResource`)**: Реализован механизм сложной фильтрации задач по нескольким критериям (проект, заголовок, исполнитель, статус, архив).
- **Система комментариев**: Реализована возможность добавления, редактирования и удаления комментариев к задачам с отслеживанием факта редактирования (`isEdited`).
- **Система вложений (`FileResource`)**: Реализована загрузка и скачивание файлов, привязанных к задачам. Файлы физически хранятся в папке `uploads`, а метаданные — в БД.

## 3. Документация и Интеграция
- **OpenAPI**: Создан файл `openAPI.md` с полным описанием всех REST-эндпоинтов в формате OpenAPI 3.0. Документация готова для генерации Angular-клиента.

## 4. Тестирование и Качество
- **Обновление существующих тестов**: Все старые тесты адаптированы под новую схему с числовыми ID.
- **Новые тесты**: Созданы интеграционные тесты для всех новых модулей:
    - `ProjectStatusResourceTest`
    - `FindResourceTest`
    - `CommentResourceTest`
    - `FileResourceTest` (включая проверку Multipart загрузки).
- **Результат**: Все 25 тестов проходят успешно (`BUILD SUCCESS`).

## 5. Оптимизация и AI производительность
- **Ускорение старта**: Удалены избыточные операции сканирования файловой системы при запуске приложения (`@Startup` убран из FS-сервисов).
- **Приоритет AI-заглушки**: Настроена приоритезация `NoOpEmbeddingModel` (@Alternative + @Priority), что исключает задержки при попытках подключения к Ollama и обеспечивает мгновенную загрузку страниц.
- **Отказоустойчивость конфигурации**: Добавлены значения по умолчанию для AI-настроек в `ConfigResource`, предотвращающие ошибки при отсутствии параметров в `application.properties`.


## 6. Трекинг времени (Time Tracking)
- **Гибридная система**: Реализован гибридный подход:
    - `totalSeconds` на уровне задачи для быстрой агрегации.
    - Таблица `timeEntries` для детального аудита (кто, когда, сколько, описание).
- **Инфраструктура**:
    - Новая таблица `timeEntries` с индексами (`taskId`, `userId`, `startTime`).
    - API эндпоинты: `POST /api/tasks/{taskId}/time` (логирование), `GET /api/tasks/{taskId}/time` (сумма).
- **Производительность**: Агрегация времени выполняется через SQL `sum(seconds)` на уровне базы данных, обеспечивая высокую скорость отчетов.



## 7. Система ролей и прав (RBAC/Actions)
- **Модель Actions**: Реализована атомарная система прав на основе действий (`Action`), таких как `task:create`, `project:update` и др., как описано в `openapi4.yaml`.
- **Иерархия ролей**: Внедрена поддержка иерархии ролей (`Admin` -> `Manager` -> `Developer` -> `Guest`). Права вышестоящих ролей включают права нижестоящих.
- **Инфраструктура**:
    - Сущность `ProjectRoleEntity` с автоматической конвертацией списка прав из JSON в БД.
    - `PermissionService` для рекурсивной проверки прав с учетом иерархии.
    - API эндпоинт `POST /api/permissions/check` для проверки доступа.

## Итог
Проект переведен на промышленную структуру данных, оптимизирован для быстрого запуска и готов к масштабированию и интеграции с современными фронтенд-фреймворками.
