# Инициализация БД через INIT=RUNSCRIPT

Этот способ используется в проекте **`TaskOne11`**.

## Где находится конфигурация
Файл настроек: `TaskOne11/src/main/resources/application.properties`

```properties
quarkus.datasource.jdbc.url=jdbc:h2:file:./task5;INIT=RUNSCRIPT FROM 'classpath:schema-h2-v2.sql'
```

## Что нужно для работы

1.  **Наличие SQL-файла**:
    Файл `schema-h2-v2.sql` должен находиться в папке **`src/main/resources/`**. Использование `classpath:` в пути позволяет Quarkus найти файл внутри ресурсов приложения (в скомпилированном JAR или в папке классов при разработке).

2.  **Отключение автоматической генерации Hibernate** (опционально, но рекомендуется для чистоты):
    Если вы используете свой SQL-скрипт для создания таблиц, лучше отключить автоматическую генерацию Hibernate, чтобы избежать конфликтов:
    ```properties
    quarkus.hibernate-orm.database.generation=none
    ```

3.  **Использование H2**:
    Этот метод специфичен для драйвера H2. Если вы планируете сменить базу данных в будущем, этот SQL-скрипт придется адаптировать под диалект новой СУБД.

4.  **Разделение для тестов**:
    Для тестов можно настроить отдельный скрипт или использовать in-memory базу:
    ```properties
    %test.quarkus.datasource.jdbc.url=jdbc:h2:mem:testdb;INIT=RUNSCRIPT FROM 'classpath:schema-h2-v2.sql'
    ```

## Плюсы подхода
*   **Полный контроль**: Вы исполняете именно тот SQL-код, который написали.
*   **Гибкость**: Можно легко добавлять сложные индексы, представления (VIEW) и триггеры, которые трудно реализовать через стандартные аннотации JPA.
*   **Изоляция**: Легко подменить скрипт инициализации для разных сред (например, тестовые данные для `%test` профиля).
